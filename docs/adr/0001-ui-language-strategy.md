# 界面语言策略：浏览器判定默认，账户级可空偏好，URL 不承载语言

为支持 `en` / `zh-Hans` 双语，界面语言的默认值由浏览器语言**判定**得出（任何 `zh-*` 前缀 → `zh-Hans`，其余回退 `en`）；用户的显式选择存为账户上的**可空**语言偏好字段（`language`），NULL 表示持续跟随浏览器（而非注册时固化快照）；URL 不携带语言段。未登录页面的显式切换仅为临时状态，在登录/注册成功后上行写入账户偏好，浏览器自动判定的结果永不固化。

## Considered Options

- **localStorage 设备级存储**——否决：不跨设备；账户才是语言偏好的唯一持久来源
- **账户字段 + 注册时固化浏览器语言**——否决：固化值会过期（用户更换浏览器/设备语言后不再匹配），可空 + 每次判定无此问题
- **URL 语言段（`/zh/...`）**——否决：登录后使用的应用型产品，SEO 收益不存在，路由与链接改造成本不值

## Consequences

- `language` 列、`GET/PATCH /users/me` 契约与重新生成的 TS client 均锚定本决策；将来若引入 URL 语言段，应作为路由层新增（读取并覆盖账户偏好），而非推翻本方案
- 第二期邮件翻译复用同一偏好字段：邮件语言 = 收件人账户语言偏好，NULL 回退 `en`（邮件没有浏览器上下文，无法判定）
